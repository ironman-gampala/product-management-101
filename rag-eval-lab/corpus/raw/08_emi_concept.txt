Overview
Converting a purchase transaction to Equated Monthly Installments(EMI) is a common service offered by Banks & Financial Institutions.It allows the customer to pay for the high value transaction over a period of time instead of making a lump sum payment.These debit transactions may have occurred on different types of Accounts. These accounts could be Revolving Credit, CASA or Prepaid.

Below are the high level features of such an EMI:

	•	Eligibility: 
	•	Not all transactions are eligible for conversion to EMI. Banks usually specify the type of transactions eligible for such conversion. There are restrictions based on the amount of transaction, merchant category codes etc. For example: transactions above Rs.5000 can be converted to EMI
	•	Certain set of customers may not be eligible for availing EMI option, say a delinquent customer, who does not pay his dues regularly may not be eligible for transaction conversion to EMI
	•	Tenure:Banks generally have fixed tenures associated with EMI such as 3 months, 6 months, 12 months, 24 months etc. Customer needs to chose among the available list of tenures 
	•	Processing Fee: Transaction conversion to EMI is generally associated with a processing fee, which can be a fixed amount or % of the transaction amount
	•	Interest Rate: Banks charge interest on the converted amount. Interest rate may vary based on the Customer Profile, Customer relationship with the bank, tenure chosen etc. Sometimes there can be interest free EMIs as part of promotion programs
	•	EMI Payments: Customers need to pay the EMI amount every month, till the loan tenure is completed. In case of EMI on credit card transactions, EMI is generally added as part of the credit card bill.In other cases, it can be recovered based on the repayment instruction given by the customer
	•	Early Repayment: Customers may choose to pay the loan amount before its maturity. Such payment can be in full or in part. Early repayments are based on the terms and conditions specified by the bank.Some banks may allow such early repayment, while others disallow. Also it can be associated with a fee for such early repayment. In case customers repay the entire outstanding amount, the loan can be pre closed. If partial payment is done, loan can be reamortized
	•	Loan Cancellation: In few exceptional scenarios, customers may choose to cancel the transaction conversion to EMI.Allowing such cancellation is again conditional, based on the terms set by the bank. For ex: Bank may set a cooling period, within which cancellation is allowed
	•	Initiating Transaction Conversion to EMI: Customers may opt for transaction conversion to EMI either at the time of purchase or post purchase. Post purchase he can convert either from mobile app, bank website or by calling the customer care
Transaction Conversion to EMI in Tachyon Credit
In Tachyon Credit, Transaction conversion to EMI is handled as a generic use case. A Debit transaction done to  any of the accounts, say Credit Card, Debit card can be converted to EMI.The end to end orchestration of Transaction Conversion to EMI and the lifecycle use cases are handled in ‘AION’. Loan Accounts are opened in Emerald

Below mentioned use cases are supported as part of Transaction Conversion to EMI:
	•	Set up and manage criteria for Conversion
	•	Convert debit transaction to a Loan
	•	Installment billing of the Loan to the underlying account
	•	Cancellation of Loan
	•	Reamortization of Loan
	•	Pre Closure of Loan
	•	Auto PreClosure based on Days Past Due at Source Account Level
	•	Provide various Inquiry APIs 
	•	Publish Business Events

AION Request Flow

All the requests related to Transaction Conversion to EMI and it’s life cycle processing is routed via AION. Each request involves multiple steps and status at each step is tracked in AION

Transaction Conversion to EMI(Loan)
Transaction conversion may be triggered in the following ways

	•	An external entity, say Turbo, identifies the transactions to be converted and calls AION service for Transaction Conversion to Loan
	•	Customer/Support Center/Ops Center may select one or more transactions in the user interface and request for conversion

Conversion Flow
Below diagram depicts the flow of ‘Transaction Conversion to EMI’



	•	When there is a request for transaction conversion to loan, such a request gets logged in AION
	•	Validations: Below specified validations are done 
	•	Product & Policy Level Validations
	•	If the Loan Type chosen is allowed at policy level
	•	If the Product ID is as per configuration or not
	•	Minimum and Maximum Loan Amount Validation
	•	Minimum and Maximum Loan Tenure Validation
	•	Account Level Validations
	•	Life Cycle Status Validations
	•	Bundle Status Validation
	•	Transaction Level Validations
	•	Minimum Transaction Amount Validation
	•	If MCC is part of Disallowed MCC category
	•	If Transaction is already converted to Loan or not
	•	If Transaction date is within the Max number of days allowed for conversion or not
	•	If validations are successful, request is marked as ‘Accepted’, else gets rejected
	•	Further Emerald Processing is done
	•	Opening of Loan Account and Disbursement
	•	Generation of Repayment Schedule
	•	Source Processing is done once Emerald Processing is completed
	•	Credit of Loan Amount
	•	Debit of Processing Fee
	•	Annotation of the converted transaction with Loan Account Number
	•	Once Source Processing is completed, an event gets generated with Request and Loan Account Details.
	•	The request gets marked as ‘Completed’

Refund Processing
	•	There can be refunds against the transaction which got converted to a Loan. Refund amount gets credited to the source account
	•	When a refund is credited to 
	•	If ‘Auto Refund Processing’ is set as ‘Yes’, such refunds automatically get adjusted against loan dues 
	•	Below parameters impact Refund Processing:
	•	Reamortization Threshold:
	•	Repayment Policy→ Min Installments for Partial Pay Off
	•	Repayment Policy→ Min Amount For Partial Pay Off
	•	PreClosure Threshold:
	•	Closure Policy→ Auto PreClosure Threshold Percentage
	•	Cancellation Period:
	•	Loan Conversion Policy→ Period For Loan Cancellation On Refund
	•	If refund amount meets , PreClosure Threshold and if such refund is received within ‘Period for Loan Cancellation on Refund’, loan gets canceled
	•	If refund amount meets , PreClosure Threshold and if such refund is received beyond ‘Period for Loan Cancellation on Refund’, loan gets preclosed
	•	If Refund does not meet PreClosure Threshold but meets Reamortization Threshold, then loan gets reamortized
	•	If none of the above conditions satisfy, such refund amount is kept in Source account itself
Loan Reamortization
Whenever refund amount is meeting reamortization threshold and if other validations are successful, Loan Reamortization is done

	•	Parameters Impacting Loan Reamortization:
	•	Amortization Policy→ Auto Reamortization Allowed
	•	Amortization Policy→ ResidualAmountValidationAllowed
	•	Amortization Policy→ ReAmortizationMethod 
	•	Repayment Policy→ Partial PayOff Allowed
	•	Repayment Policy→ Min Installments for Partial Pay Off
	•	Repayment Policy→ Min Amount For Partial Pay Off
	•	Loan reamortization here would mean adjusting such refund amount against Principal Outstanding and then redrawing of the schedule based on revised principal amount, applicable interest rate, tenor etc
	•	Loan Balance which is maintained at Source account level also gets reduced to the extent of reamortization amount
Loan Cancellation
Loan Cancellation can be triggered based on Automatic Refund Processing or based on Customer Request
	•	Parameters Impacting Loan Cancellation:
	•	Closure Policy→Allow Loan Cancellation
	•	Closure Policy→Cooling Period for Loan Cancellation
	•	Loan Conversion Policy→ Period For Loan Cancellation On Refund
	•	When loan cancellation validations are successful, loan gets canceled
	•	As part of loan cancellation, Interest Income booked if any gets reversed
	•	Loan status gets marked with the Status as ‘Closed’ and Sub Status as ‘Canceled
	•	Once Emerald Processing is done, source processing is triggered
	•	As part of source processing, installment billed if any, gets reversed with value date as loan cancellation date
	•	The loan credit given as part of transaction conversion to EMI, gets reversed
	•	Value set for the field ‘Processing Fee Reversal on Loan Cancellation’ in Loan Conversion Policy decides if processing fee to be reversed on loan cancellation or not
	•	Loan Account Number Annotation is removed from the source transaction id
	•	Once source processing is done, AION emits an event with Loan Cancellation details, which can be used to send notifications to the end customer

Loan PreClosure
The Borrower may decide to close the loan before the Maturity Date. In some cases even IFI may decide to close the loan account before the maturity. If the account gets closed before actual maturity, it would be termed as ‘Pre Closure’.
	•	Parameters Impacting Loan PreClosure:
	•	Closure Policy→Allow PreClosure
	•	Closure Policy→PreClosure Lock In
	•	Closure Policy→AutoPreclosure threshold Percentage
	•	When loan preclosure validations are successful, loan gets preclosed
	•	Preclosure amount is calculated. Preclosure amount consists of 
	•	Principal Outstanding Balance
	•	Catch Up Interest
	•	GST On CatchUp Interest
	•	PreClosure Fee if any
	•	GST on Processing Fee
	•	Loan status gets marked with the Status as ‘Closed’ and Sub Status as Preclosed’
	•	Once Emerald Processing is done, source processing is triggered
	•	As part of source processing, Preclosure Amount gets debited to the source account and loan balance gets updated
	•	Once source processing is done, AION emits an event with Loan Preclosure details, which can be used to send notifications to the end customer
