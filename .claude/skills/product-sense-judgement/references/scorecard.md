# Scorecard

Use after a mock or when reviewing a pasted answer. Be direct: the learner is deciding whether they
are ready for real loops, so a soft verdict wastes their time. Score what they did, not what they
did after a hint — note hints separately.

## 1. Weak-spot table (first)

If the learner profile lists weak spots, score each one:

| Weak spot | What happened today | Status |
|---|---|---|
| … | specific moment from the mock | 🟢 fixed / 🟡 improving / 🟠 half / 🔴 still there |

Then one line: **the big insight from today** — the single habit that caused most of the losses.

## 2. Step scores (out of 10)

| Step | 4/10 looks like | 7/10 looks like (L4 pass) | 9/10 looks like (L5 strong) |
|---|---|---|---|
| Clarify | One question at a time, no market picked | Batched questions, assumptions stated | Questions that genuinely reshape the problem; narrows a broad prompt early |
| Strategy + NSM | Jumps to a metric; metric is a count + rate mix | Mission, why company, one measurable NSM | Specific why-now, NSM that measures outcome and survives solution changes, defended out loud |
| Users | One user found; mixes in pain stories | 3–4 one-liners, a pick with reasons | Lenses stated, pick + explicit reject of the obvious runner-up, B2B roles named where relevant |
| Pain points | List of complaints | Journey walk, 3 pains, one picked | Vivid persona, pick by frequency × severity, problem statement with a sharp "because" |
| Solutions | One idea, detailed immediately | 3 distinct ideas, one picked | 3 lenses incl. an "only we can do this" idea; pick tied to root cause or dependency |
| Solution flow | Screen only | Entry → screen → action → result | All six steps incl. behind-the-scenes data and an honest edge case |
| MVP + metrics | Scope without prerequisite; v1 contradicts logic | Prerequisite, v1, what waits | Consistent with earlier logic, guardrails that could break while NSM rises, second-order effect, reversal line |
| Communication | Filler, "so yeah", asks interviewer for help | Clear, mostly signposted | Calm, drives the room, transition lines, crisp close |

Give each step a score, one "what landed" and one "what to fix".

## 3. Overall level read

| Overall | Read |
|---|---|
| ≤ 5 | Below PM2 bar. Interviewer had to drive. |
| 6 | Borderline L4. Structure is there with prompts. |
| 7 | L4 / PM2 pass. Runs the route alone, some thin judgement. |
| 8 | Strong L4, borderline L5. Decisions + rejects at most steps. |
| 9+ | L5 / Senior pass. Drives the room, sharp strategy, consistent trade-offs. |

State the verdict for each target level the learner is interviewing for (e.g. "PM2: lean reject.
Senior: reject."), with the reason in one sentence each. Separate "resume screen" from "case round"
if they ask about screening.

## 4. Fix the weakest step

Write the model turn for the weakest step only (spoken, full sentences), so they leave with one thing
to rehearse rather than a pile of notes.

## 5. Drill plan

Three short daily drills, each mapped to a weak spot. Defaults:
- **Users in 60 seconds:** any app → two lenses → four users → pick one.
- **Three ideas before detail:** any problem → three one-liners in 90 seconds.
- **Flow in 2 minutes:** say all six flow steps for one idea out loud.

## 6. Log it

If `My Profile/` exists, log the session in `My Profile/Daily Practice/`: a new day file plus updates to
`Index.md` (see SKILL.md → Learner profile). With an older single `My Profile.md`, append a mock log row: date | question | type | score | key notes.
